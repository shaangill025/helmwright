# Owner decisions

Decisions the owner made for helmwright, with the options that were rejected. Design references
(`03§`, `06§`, …) point to the Meta-Harness Design v2 sections; "Sept" is the September 2026
requirements document. This log is a stopgap until the decision ledger (Slice A) exists.

## Slice B (2026-10-06)

| Q                         | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Rejected                                                                           |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| Q61 object model          | Seven kinds (Task, Decision with Ruling, Run, Event, Artifact, Rule, Skill). Links are typed ID fields (arrays for many-to-many, e.g. `rule.evidenceDecisionIds`, `decision.footprint`) on the referencing object, written when it is created. A Ruling is a Decision with `authority: "harness"` and cannot carry owner-only fields; every object carries `ring`. Step up to the full ontology when a third surface needs its own view or kinds exceed ~15 (10§Ontology)                                                                                                                                                                                                                                                               | separate edge records; full ontology module                                        |
| Q26 storage               | `node:sqlite`. The events table rejects UPDATE and DELETE; object tables are projections rebuildable from events; an object change and its event commit in one transaction; the database file lives in a gitignored state directory                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | better-sqlite3; append-only JSONL                                                  |
| Q6 actions                | The September action set mapped onto the seven kinds: dispatch/move → Task, commit → Artifact, promote → Skill, resolve → Decision (card), merge(allowlist entry) → Rule (owner-only; not PR merging), edit → Rule/Skill, spawn/cancel/join → Run; plus edit/execute/validate on Artifact and the September transition state machine (requested → authorized → executing → succeeded / failed / outcome-unknown; denied; cancelled). Deploy and publish stay always-ask permission actions. Actions without an M1 caller get schemas, permissions and transition tests now; handlers arrive with their caller (proposed: cancel M1 for run termination, merge M2 with sensor exceptions, edit Rule/Skill and promote M3, spawn/join M4) | add the September kinds; minimal M1 set; shell filter                              |
| Q51 config                | `helmwright.config.json` validated by its own schema; Ring 0 settings (08) are always-ask to change; a non-default alternative is rejected until it has a fixture (07 rule 1). Always-ask set: deploy; delete outside the run worktree; network egress or external side effects (push, publish, comment) other than engine traffic through the credential proxy; raising the spend cap; changing governance mode or any Ring 0 setting; editing Ring 0 paths when dogfooding                                                                                                                                                                                                                                                            | YAML; TypeScript config                                                            |
| Q60 rot register          | `rot-register.json` with {component, ring, assumption, evidence, added, lastReviewed, reviewTrigger}, schema-validated; CI fails when a module has no entry; admitting a new engine version or model ID emits `rot.reviewDue`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | markdown table; inline annotations                                                 |
| Q52 intake                | Deterministic rule table: architectural if a new package or module, schema / public API / storage / wire change, dependency-set change or new process boundary; bounded if inside existing modules within declared scope; chore if docs, formatting or tests only, except protected tests and eval paths, which are at least bounded. Owner override recorded as an event (old class, new class, reason). The harness may only reclassify upward                                                                                                                                                                                                                                                                                        | owner classifies by hand; model classifies                                         |
| Native engine models      | Deviation from 10§Roles and 06§Hands two-tier routing, chosen by the owner: `claude-opus-5-5` for every role, effort set per role (one model, one cache namespace). Model IDs are pinned in the capability registry; the routing file is Ring 1. Revisit with measured cost per completed task at the M1 'what can we stop doing' review                                                                                                                                                                                                                                                                                                                                                                                                | Opus/Sonnet/Haiku split; Fable 5.1 for planner/evaluator                           |
| Native engine credentials | A separate local credential proxy reads the key from macOS Keychain, forwards only to the Anthropic API and enforces the spend cap; harness and sandbox environments never contain the key                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | harness reads Keychain; `ant auth login` profile                                   |
| Hosted engine             | Claude Code runs on the host with its own subscription login and its built-in tools disabled; its only tools are harness tools that go through the broker and execute in the sandbox; the structural floor still inspects the diff. Disabling the built-in tools must be proven by a capability-registry conformance test before the engine is admitted                                                                                                                                                                                                                                                                                                                                                                                 | Claude Code in the container; native tools allowed                                 |
| Q59 capability registry   | Entry: engine, exact version, binary digest, model ID (native), auth mode, sandbox image digest, policy version, conformance-suite version, evidence digest, status, revocation epoch. Dispatch and every tool call in a running session check the epoch, so revocation overrides a pin, including mid-run                                                                                                                                                                                                                                                                                                                                                                                                                              | version pin only; hardcoded allowlist                                              |
| Q58 untrusted content     | Acting engines have no fetch/web tools and the sandbox has no egress. Third-party text (web pages, dependency docs and `node_modules`, issues, other authors' files) is read only by an explore-role session with no privileged actions (an M1 stand-in for 10's Researcher role, M2), which returns a hint capped at 1024 bytes (Ring 0 config) and screened deterministically                                                                                                                                                                                                                                                                                                                                                         | block all third-party content in M1; model-based detector                          |
| Q5 replay                 | Native engine: rebuild projections and derived context from the log, compare digests, and re-run the loop against recorded responses with byte-identical requests.
